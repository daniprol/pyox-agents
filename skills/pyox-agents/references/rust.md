# Rust tools, hooks and history stores

A Rust extension for pyox-agents is a normal PyO3 + maturin package that depends on the `pyox-tools` crate.
Copy one of the examples as a starting point:

- Tools and hooks: https://github.com/daniprol/pyox-agents/tree/main/examples/rust_tool_package
- History store (SQLite with sqlx): https://github.com/daniprol/pyox-agents/tree/main/examples/rust_history_store

## Package setup

`pyox-tools` is not on crates.io. Depend on it from git, pinned to the tag of the pyox-agents version you use:

```toml
# Cargo.toml
[lib]
name = "fast_tools"
crate-type = ["cdylib"]

[dependencies]
pyo3 = { version = "0.30.1", features = ["abi3-py311"] }
pyox-tools = { git = "https://github.com/daniprol/pyox-agents", tag = "v0.1.0" }  # match your pyox-agents
schemars = "1.2"
serde = { version = "1.0", features = ["derive"] }
```

```toml
# pyproject.toml
[build-system]
requires = ["maturin>=1.0,<2.0"]
build-backend = "maturin"
```

Install with `uv pip install ./path/to/package` (needs a Rust toolchain). A tool built against a different
native interface version is rejected with a `ValueError` naming both versions: rebuild against the matching tag.

## Tools

One struct per tool. The struct is the argument schema (generated by `schemars`); doc comments become the
descriptions the model reads.

```rust
use pyo3::prelude::*;
use pyox_tools::{RustTool, add_tool};
use schemars::JsonSchema;
use serde::Deserialize;

/// Find the most frequent words in a text.
#[derive(Deserialize, JsonSchema)]
struct MostCommonWords {
    /// The text to analyze.
    text: String,
    /// How many words to return (default 5).
    top: Option<usize>,
}

impl RustTool for MostCommonWords {
    const NAME: &'static str = "most_common_words";

    fn run(self) -> Result<String, String> {
        // Ok(text) is the tool result; Err(message) is sent to the model as an error.
        Ok(String::new())
    }
}

#[pymodule]
fn fast_tools(module: &Bound<'_, PyModule>) -> PyResult<()> {
    add_tool::<MostCommonWords>(module)?;
    Ok(())
}
```

Python: `Agent(tools=[fast_tools.most_common_words])`. `run` is synchronous and runs on a Rust thread; it does
not get the run context.

## Hooks

```rust
use pyox_tools::hooks::{Hooks, add_hooks};

let guard = Hooks::new()
    .before_tool_call(|_context, call| {
        if call.name == "delete_file" {
            return Err("Deleting files is not allowed".into()); // blocks the call; the model sees this
        }
        Ok(())
    })
    .before_model_request(|_context, request| {
        // `request` is `&mut ModelRequest` (messages, model_parameters...): changes apply to this request only.
        Ok(())
    });
add_hooks(module, "guard", guard)?; // inside #[pymodule]; Python: Agent(hooks=[fast_tools.guard])
```

Builder methods: `before_run`, `before_model_request`, `after_model_response`, `before_tool_call`,
`after_tool_call`, `after_run`. Closures get `&mut` access to what they may change. Signatures:
`crates/pyox-tools/src/hooks.rs`.

## History stores

Implement `HistoryStore` (async `load`, and optionally `save`) on a struct holding your connection pool, and wrap it in
`RustHistoryStore`:

```rust
use pyox_tools::history::{HistoryStore, RustHistoryStore, runtime};
use pyox_tools::messages::Message;

struct MyStore { /* pool */ }

impl HistoryStore for MyStore {
    async fn load(&self, conversation_id: &str) -> Result<Vec<Message>, String> { todo!() }
    async fn save(&self, conversation_id: &str, new_messages: &[Message]) -> Result<(), String> { todo!() }
}
```

Expose a `#[pyfunction]` that creates the pool inside `runtime()` (release the GIL with `py.detach`) and returns
`RustHistoryStore::new(MyStore { ... })`. Python: `Agent(history_store=my_package.my_store(...))`. `Message`
serializes to the same JSON as the Python history dicts.

## Style

Code in this ecosystem is written for Python developers: plain names, no clever generics or macros, and comments
that explain Rust-specific ideas. Keep `run` small and return `Err(String)` instead of panicking.
